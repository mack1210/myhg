01

도시락을 만든다고 생각해 보세요.

chezmoi는 재료 목록을 읽고 조리법에 맞춰 설정 파일을 만드는 도구예요.

  1. 01 / INGREDIENTS

    재료 목록

    앱 이름 같은 값을 모아요.

    .chezmoidata.yaml
  2. 02 / RECIPE

    빈칸이 있는 양식

    어디에 넣을지 정해요.

    .tmpl
  3. 03 / CHEZMOI →

    완성된 설정 파일

    chezmoi가 빈칸을 채워요.

    .friend-ai.env
  4. 04 / READY TO USE

    프로그램에 전달

    앱이나 셸이 파일을 읽어요.

    환경변수 → AI 앱

●환경변수는 프로그램이 읽는 이름표예요. 데이터 파일을 만드는 것만으로 자동 등록되지는 않아요.

02

한 번 바꾸고, 다른 컴퓨터에도 한 번에.

GitHub에 내 조리법 책을 두면 컴퓨터마다 설정을 다시 복사하지 않아도 돼요.

  1. 01 / COMPUTER A →

    내 컴퓨터에서 바꾸기

    데이터와 양식을 고치고
    관리 파일에 일괄 적용해요.

    chezmoi apply
  2. 02 / GITHUB →

    내 dotfiles에 올리기

    Git으로 변경을 기록하고 올려요.
    자동 커밋·푸시도 켤 수 있어요.

    commit + push
  3. 03 / COMPUTER B

    한 명령으로 받아 쓰기

    최신 설정을 내려받고
    관리 파일들에 함께 반영해요.

    chezmoi update

설정 파일 세 개가 같은 app.name을 읽는다면? 데이터 한 곳만 바꿔도 세 파일을 함께 새로 만들어요.

apply는 현재 소스를 적용, push는 소스를 올리기, update는 내려받기 + 적용이에요.

내 상황에 맞는 네 가지 실전 모식도 보기 ↓
01처음 연결하는 컴퓨터

Git이 설치돼 있고 내 dotfiles에 데이터와 양식이 올라가 있다면, YOUR_NAME을 내 계정으로 바꿔 실행해요.

# 처음 한 번: 내 설정 저장소를 내려받고 적용합니다.
chezmoi init --apply https://github.com/YOUR_NAME/dotfiles.git

이 명령은 실제 홈 설정을 바꿔요. 믿을 수 있는 내 저장소를 사용해요.

myhg는 이 설명서이고, 동기화할 설정은 별도의 dotfiles 저장소에 둬요. 작성자는 mack1210/dotfiles를 사용해요.

02컴퓨터 A에서 바꾸고, B에서 한 번에 받기

컴퓨터 A · 수정하고 올리기

chezmoi source-path 폴더의 데이터와 양식을 수정한 뒤 실행해요. 아래는 이 문서의 비밀 없는 예제이며, Git 작성자 정보와 원격 인증이 준비돼 있어야 해요.

# 관리 중인 양식들에 값을 채워, 이 컴퓨터에 일괄 적용합니다.
chezmoi apply
# 데이터와 양식을 기록하고 GitHub로 올립니다.
chezmoi git add .chezmoidata.yaml private_dot_friend-ai.env.tmpl
chezmoi git -- commit -m "Update AI app settings"
chezmoi git push

일반 설정 파일을 홈에서 직접 고쳤다면 chezmoi re-add <파일>로 먼저 소스에 담아요. 템플릿 값은 데이터·양식을 고치고, 기존 암호화 방식은 유지해요.

컴퓨터 B · 내려받고 일괄 적용하기

# GitHub에서 최신 설정을 받고, 관리 파일들에 일괄 적용합니다.
chezmoi update

컴퓨터마다 데이터가 다르면 완성 파일도 달라질 수 있어요. 실행 중인 앱은 설정을 다시 읽거나 재시작해야 할 수 있어요.

03커밋·푸시까지 자동으로 처리하기

각 컴퓨터에서 chezmoi 자체 설정을 열어요.

chezmoi edit-config

TOML 설정을 쓰면 ~/.config/chezmoi/chezmoi.toml의 기존 [git] 항목에 합쳐요. 기본값은 꺼져 있으며, .chezmoidata.yaml에 넣는 값은 아니에요.

[git]
    autoCommit = true
    autoPush = true

chezmoi add·re-add·edit 같은 명령으로 소스를 바꿀 때 커밋·푸시를 자동 처리해요. 편집기로 직접 고친 모든 순간을 감시하는 기능은 아니므로 기록·푸시 여부를 확인해요.

다른 컴퓨터에서는 여전히 chezmoi update를 실행해요. 정기적으로 자동 반영하려면 별도 예약 실행이 필요해요.

자동 푸시를 켜면 잘못 담은 비밀값도 바로 올라갈 수 있어요. pass 저장소와 GPG 키는 이 연결만으로 복제되지 않으므로 따로 준비해요.

업데이트 충돌이나 푸시 오류가 나면 변경 내용을 확인해 해결하고, 강제 푸시로 덮어쓰지 않아요.

CASE 01 / ONE VALUE, THREE FILES

스터디 앱 이름을 세 설정에 함께 바꾸기

AI 채팅·명령 도구·작업 도구의 앱 이름을 friend-ai에서 study-ai로 바꾸고 싶어요.

준비: 앞선 양식을 mirror·worker 양식으로 복사해 Git에 저장했고, 세 양식이 모두 .app.name을 읽는 상황이에요. 이 사례는 자동 커밋·푸시를 끈 기본 설정이며, 자동화는 Case 3에서 다뤄요.

A의 chezmoi source-path 폴더에서 .chezmoidata.yaml을 이렇게 바꿔요.

app:
  name: study-ai
  environment: practice

① 컴퓨터 A · 반영하고 올리기

chezmoi apply
chezmoi git add .chezmoidata.yaml
chezmoi git -- commit -m "Rename AI study app"
chezmoi git push

② 컴퓨터 B · 내려받고 적용하기

chezmoi update
결과 · 값 한 번 수정 → 두 컴퓨터의 세 설정에 반영

파일 이름은 그대로이고 안의 앱 이름이 바뀌어요. 실행 중인 도구는 설정을 다시 읽게 하거나 재시작해요.

CASE 02 / A FRESH START

새 노트북에서 내 작업 환경 시작하기

노트북을 바꿨어요. 예전에 정리한 설정을 다시 쓰고 싶어요.

준비: Git·chezmoi 설치, 내 dotfiles 접근 권한. 명령의 YOUR_NAME은 내 GitHub 계정으로 바꿔요.

새 노트북에서 순서대로 실행

# 먼저 내 저장소를 내려받습니다.
chezmoi init https://github.com/YOUR_NAME/dotfiles.git
# 비밀값을 쓰면 이 단계 전에 pass 저장소·GPG 키를 따로 준비합니다.
chezmoi apply

금고까지 준비돼 있다면?

앞선 init --apply로 내려받기와 적용을 한 번에 할 수 있어요.

프로그램 설치 자체는 별도예요. dotfiles에 설치 자동화를 따로 작성한 경우에만 그 작업도 수행돼요.

결과 · 새 노트북에 관리 설정이 만들어져요.

설정 원본은 Git에서, 비밀값은 별도로 준비한 금고에서 가져와요.

CASE 03 / EDIT, CAPTURE, SHARE

홈에서 바꾼 일반 설정을 자동으로 올리기

A의 ~/.friend-settings.conf에서 theme=green을 theme=dark로 바꿨어요.

준비: 이미 관리 중인 비밀 없는 일반 파일이며, A의 autoCommit·autoPush가 켜져 있어요.

① 컴퓨터 A · 다시 담고 자동으로 올리기

chezmoi re-add ~/.friend-settings.conf

② 컴퓨터 B · 내려받아 적용하기

chezmoi update
결과 · B의 같은 파일에도 theme=dark

자동화를 껐다면 직접 커밋·푸시해요. 템플릿은 re-add 대신 데이터·양식을 수정하고, 새 파일은 관리 방식을 정한 뒤 add로 등록해요.

CASE 04 / A NEW KEY, THE SAME ADDRESS

API 키만 새 키로 교체하기

AI 서비스에서 새 키를 발급받았어요. 양식은 그대로 쓰고 키만 바꾸고 싶어요.

준비: .friend-ai.env 양식이 데이터에 적힌 api/openai/api_key 경로에서 키를 읽고 있어요.

① 키를 바꿀 컴퓨터 · 금고 값 교체

덮어쓰기 질문을 확인하고 새 키는 입력 창에 입력해요.

pass insert api/openai/api_key

② 같은 컴퓨터 · 파일을 다시 만들기

chezmoi apply ~/.friend-ai.env
결과 · 키만 바뀌므로 dotfiles 커밋·푸시는 필요 없어요.

다른 컴퓨터의 금고에도 새 값을 별도로 준비한 뒤 각자 apply해요. pass 저장소의 별도 동기화를 쓴다면 그 절차를 따라요.

키가 출력될 수 있는 diff로 교체 결과를 확인하지 않아요.

03

이름 하나 바꾸면, 설정도 따라와요.

아래 값을 바꾸고 재료 → 양식 → 결과를 눌러 보세요.

나의 작은 AI 앱

한곳에 적은 값을 여러 설정에서 함께 쓸 수 있어요.

미리보기 전용이에요. 실제 설정은 바뀌지 않아요.

.chezmoidata.yaml

app:
  name: "friend-ai"
  environment: "practice"

private_dot_friend-ai.env.tmpl

APP_NAME={{ .app.name | quote }}
APP_ENV={{ .app.environment | quote }}

.friend-ai.env

APP_NAME="friend-ai"
APP_ENV="practice"

여기에 값을 모아요. 다른 양식에서도 같은 값을 꺼내 쓸 수 있어요.

{{ .app.name }}은 “목록의 app 안에서 name을 꺼내 줘”라는 뜻이에요.

04

비밀값 대신, 금고 칸 이름을 적어요.

API 키는 AI 서비스에 들어가는 열쇠예요. pass는 그 열쇠를 보관하는 금고예요.

KEEP THE KEY IN THE VAULT

공유하는 건 조리법까지.

Git은 설정의 변경 기록이자 전달 통로예요.
재료 목록과 양식은 공유하고,
실제 키가 들어간 완성 파일은 내 컴퓨터에 둬요.

  1. pass에 실제 키를 보관해요.

    예: api/openai/api_key라는 칸에 저장해요.

  2. 재료 목록에는 칸 이름만 적어요.

    비밀값 없이 “어디에서 꺼낼지” 알려 줘요.

  3. 필요할 때 chezmoi가 꺼내 채워요.

    완성 파일에는 실제 키가 들어가요. 이 파일과 출력 내용은 공유하지 않아요.

06

이제 직접 만들어 볼까요?

처음에는 비밀값 없이, 임시 폴더에서 연습해요.

준비물: chezmoi가 설치된 Bash · 아래 단계는 같은 터미널에서 순서대로 진행해요.

01실습용 폴더 준비하기

실제 홈 설정과 분리된 작은 작업실을 만들어요.

demo_dir=$(mktemp -d)
mkdir -p "$demo_dir/source" "$demo_dir/home"
printf '{}\n' > "$demo_dir/config.json"
cm() {
  chezmoi --config "$demo_dir/config.json" \
    --source "$demo_dir/source" --destination "$demo_dir/home" \
    --cache "$demo_dir/cache" --persistent-state "$demo_dir/state.boltdb" "$@"
}
02재료 목록과 양식 저장하기

아래 경로에 파일 두 개를 만들고 각각 내용을 저장해요.

재료 목록

$demo_dir/source/.chezmoidata.yaml

app:
  name: friend-ai
  environment: practice

양식

$demo_dir/source/private_dot_friend-ai.env.tmpl

APP_NAME={{ .app.name | quote }}
APP_ENV={{ .app.environment | quote }}

dot_은 파일 이름의 점, .tmpl은 양식, private_는 다른 사용자의 읽기 권한을 제한하는 표시예요.

03설정 파일 만들고 프로그램에 전달하기

미리 확인한 뒤, 임시 폴더에 적용해요.

# 먼저 완성될 내용을 확인합니다. 이 실습에는 비밀값이 없습니다.
cm execute-template < "$demo_dir/source/private_dot_friend-ai.env.tmpl"
cm diff
# 확인한 내용을 임시 폴더에 만듭니다.
cm apply

완성 파일: $demo_dir/home/.friend-ai.env

APP_NAME="friend-ai"
APP_ENV="practice"

현재 Bash에서 파일을 읽으면 이후 실행하는 프로그램도 값을 받아요.

set -a
. "$demo_dir/home/.friend-ai.env"
set +a
printf '%s\n' "$APP_NAME"
# friend-ai

. 명령은 파일을 코드로 실행하므로 직접 만든 신뢰할 수 있는 파일에만 사용해요. 프로그램마다 .env를 읽는 규칙은 다를 수 있어요.

04준비가 됐다면, pass 연결하기

pass 설치와 GPG 금고 초기화를 마친 뒤 pass insert api/openai/api_key를 실행하고 입력 창에 키를 입력해요.

기존 재료 목록에 아래 항목을 합쳐요. 실제 키 대신 금고 경로만 적어요.

secrets:
  api:
    openai_api_key: api/openai/api_key

양식에 한 줄을 추가하면 pass에서 키를 꺼내 채워요.

OPENAI_API_KEY={{ pass .secrets.api.openai_api_key | quote }}

이제 diff나 execute-template 출력에도 실제 키가 나올 수 있어요. 완성 파일과 출력 내용은 Git·채팅·공유 화면에 올리지 않아요.

quote는 큰따옴표로 감싸는 기능이에요. 암호화 기능은 아니며, 특수문자가 있는 값은 사용할 프로그램의 파일 규칙을 확인해요.

05내 설정에 연결하고 예제 검사하기

chezmoi source-path가 알려주는 폴더에 실제 .chezmoidata.yaml을 둬요. 기존 항목과 합치고 같은 이름의 항목을 중복해서 만들지 않아요.

cgmoi 방식은 일반 설정은 데이터에, 비밀은 pass에 두며 이미 암호화된 양식은 암호화 상태를 유지해요.

실제 파일에 chezmoi apply를 하기 전에는 대상·변경 내용·자동 커밋 및 푸시 설정을 확인해요.

이 저장소의 예제 검사

python3 -m unittest discover -s tests -v

Python 3, chezmoi, Git으로 가짜 값과 임시 저장소의 동기화를 검사해요. 실제 홈 설정과 금고는 사용하지 않아요.

템플릿 안내 ↗ 공유 데이터 파일 ↗ pass 연결 안내 ↗ execute-template ↗ Git 연동·자동 커밋 ↗ update 명령 ↗ re-add 명령 ↗
